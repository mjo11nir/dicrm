# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Beauty CRM** — локальная PWA-CRM и расписание для бьюти-мастера (интерфейс по образцу Master Up, но со своим названием и логотипом). Работает в браузере без сервера, данные хранятся только на устройстве (IndexedDB). Основное устройство — iPhone (Safari и установка на экран «Домой»).

- ТЗ: `docs/SPEC.md`. Скриншоты-образцы: `docs/screenshots/` (если ТЗ и скриншот расходятся — верь скриншоту).
- Что сделано и что осталось: `docs/PROGRESS.md`. Все 4 этапа ТЗ выполнены; обновляй файл при заметных изменениях.

## Жёсткие правила

1. Чистые HTML + CSS + JavaScript (ES-модули), без сборщиков и npm в рантайме. Библиотеки только по CDN: Dexie.js, Chart.js, html2canvas.
2. Никаких серверов, SQL, Docker, фреймворков, регистрации и логинов. Все данные — в IndexedDB только через `js/db.js`.
3. Никаких нерабочих кнопок. То, что требует сервера, — бейдж «Скоро» с пояснением (см. `soon()` в `js/screens/profile.js`). Ещё не готовый раздел лучше скрыть, чем показать пустышку.
4. Не используй логотип и название Master Up. Иконки — Lucide или Tabler, inline SVG в `js/components/icons.js` (не эмодзи).
5. Свободные окна считаются только в `js/utils/slots.js`; тесты — `tests/slots.test.html`.
6. Интерфейс, комментарии в коде и сообщения коммитов — на русском.
7. Перед завершением работы запусти локальный сервер, открой приложение и проверь, что в консоли нет ошибок.

## Команды

```bash
python3 -m http.server 8000          # приложение: http://localhost:8000
# тесты:                               http://localhost:8000/tests/slots.test.html  (✅/❌ на странице)
```

Сборки, линтера и npm-скриптов нет. Тесты — одна HTML-страница с самописным `test()`/`eq()`; отдельный тест не запускается — закомментируй остальные или смотри строку с ❌. Итог страница пишет в `document.title` (`PASS` / `FAIL`), это удобно проверять в headless-браузере.

Публикация: GitHub Pages из ветки `main` (корень). Ссылка: https://mjo11nir.github.io/dicrm/

### Выпуск новой версии (обязательно)

Приложение работает офлайн через `sw.js`. После любого изменения файлов:
- увеличь `VERSION` в `sw.js`, иначе телефоны продолжат получать старые файлы из кэша;
- новый файл (JS/CSS/иконку) допиши в `APP_FILES` в `sw.js`, иначе он не будет доступен без интернета.

Пользователю новая версия приходит через сообщение «Доступна новая версия» → «Обновить» (`registerServiceWorker()` в `js/app.js`).

## Архитектура

**Точка входа и роутер — `js/app.js`.** Четыре вкладки (Главная, Расписание, Чаты, Другое), у каждой свой стек экранов в DOM: переключение вкладок ничего не уничтожает, поэтому вкладка помнит прокрутку и открытый подэкран. Экран — функция `(params, nav) => ({ el, refresh?, onShow?, setParams?, destroy? })`. `nav` даёт `push(Screen, params)`, `pop()`, `switchTab(id, params)` (при переходе на вкладку с параметрами вызывается `setParams` корневого экрана) и `nav.app.settings`.

**Поток данных.** Все записи идут через `save` / `update` / `remove` / `restore` из `js/db.js`. Каждая запись получает UUID, `createdAt` / `updatedAt` / `deleted` (удаление мягкое), изменение дописывается в таблицу `outbox` (задел на будущую синхронизацию с сервером) и порождает событие `window` `db:change`. `app.js` по этому событию вызывает `refresh()` у видимого экрана, а остальные помечает «грязными» и обновляет при показе. Поэтому экраны не обновляют друг друга вручную: достаточно записать в базу. Ловушка: экран, который сам автосохраняет в базу, получит `refresh()` на своё же сохранение и потеряет фокус в поле — пропусти его, как сделано в `js/screens/webpage.js` (`selfSaved`).

**Форматы данных.** Деньги — целые центы (`js/utils/money.js`: `money` → «€2.345», `moneyFull` → «€45,00»). Даты — строки `YYYY-MM-DD` по локальному времени, время внутри дня — минуты от полуночи (`start: 540` = 09:00), см. `js/utils/dates.js`. Неделя начинается с понедельника (`weekdayIndex`: 0 = пн). Запись (`appointments`) хранит копию выбранных услуг (`services: [{id, name, duration, price}]`), `price` (до скидки) и `total` (итог). Выручка везде считается по `total` завершённых записей, а не по платежам, чтобы предоплата не учитывалась дважды.

**Настройки** — таблица `settings` (ключ → значение), чтение через `getSettings()` поверх `DEFAULT_SETTINGS` в `js/db.js`. Глобальные настройки (валюта, акцентный цвет, тема, название) применяет `applySettings()` в `app.js`.

**Расчёт окон** — `js/utils/slots.js`, чистые функции без доступа к базе: `getDayHours` (график + исключения/отпуска), `getFreeIntervals` (лента дня), `getFreeSlots` / `getFreeSlotsRange` (свободные окна, точки в календаре, «Найти и записать», лист ожидания через `js/utils/waitlist.js`), `findConflicts` (проверка пересечений в форме записи). Текущее время передаётся параметром `now`, чтобы функции можно было тестировать.

**Сообщения клиентам** — `js/messaging.js`: шаблоны (`TEMPLATE_DEFS` + сохранённые в таблице `templates`), подстановка переменных `{имя}` `{дата}` … `{окна}`, открытие wa.me / t.me и сохранение копии в `messages` (из неё строится вкладка «Чаты»).

**UI-компоненты** — `js/components/ui.js`: `el()` (создание элементов), `openSheet` (лист снизу), `openModal` (модальный экран), `actionSheet`, `confirmAction`, `toast` (с `undo` или своим `action`), `groupedList` (строки iOS), `segmented`, `downloadFile`, `loadScript`. Форма записи — `js/components/appointment-form.js`, листы дня (перерыв, часы дня, поиск) — `js/components/day-forms.js`.

**Библиотеки.** Dexie подключается в `index.html` как глобальный `Dexie`. Chart.js и html2canvas загружаются по требованию через `loadScript()` при первом открытии статистики или отправке картинки; `sw.js` кэширует все три.

**Стили** — один файл `css/styles.css`. Цвета — только через CSS-переменные в `:root`. Тёмная тема — блок в конце файла: те же переменные переопределяются под `@media (prefers-color-scheme: dark)` и под `:root[data-theme="dark"]`. Новые цвета добавляй переменной в оба места, а не числом в правиле. Исключение — карточка «Свободные окна» (`.fs-card`): она превращается в картинку и всегда светлая.

**Демо-данные** — `js/demo.js`, создаются при первом запуске, если таблица `schedule` пуста. Все демо-записи помечены `demo: true` (по этому полю их удаляет «Удалить демо-данные» в «Резервной копии»). Записи строятся относительно сегодняшней даты: график пн–чт, пятница–воскресенье выходные.

**Изображения.** Фото галереи хранятся в IndexedDB как `Blob` (уменьшаются до 1600px в `js/utils/image.js`); в резервной копии они превращаются в data URL и обратно (`exportAll` / `importAll` в `js/db.js`).

## Проверка в headless-браузере

- CDN (jsdelivr) из песочницы может быть недоступен — подставляй локальные копии библиотек через `page.route('**/dexie.min.js', ...)` (их можно взять через `npm pack dexie@4.0.8` и т. п. во временную папку).
- В эмуляции iPhone при первом открытии появляется подсказка «Установите приложение», которая перекрывает нижнюю часть экрана. Отключай её заранее: `localStorage.setItem('installHintDismissed', '1')`.
- Демо-данные зависят от дня недели: в пятницу–воскресенье на Главной нет записей.
